Cloud analytics turn each device's local decision history into team-scope
dashboards. What leaves the machine is **aggregated rollups and security
events** — never command lines, paths, prompts or file contents.

Cloud analytics apply to paid plans only: the account needs an active plan
carrying both the `cloud_sync` and `usage_analytics` entitlements. It is **on
by default** once a paid account is signed in, and the daemon records a consent
receipt locally the first time it turns itself on.

## What gets sent

Aggregated rollups per UTC day, plus security events:

- **Decision counts** — allowed, queued and denied, by hour and by day.
- **Score distribution** — composite-score sums and a versioned 30-bin
  histogram over the 0–15 range.
- **Filter activity** — per-filter evaluated, triggered and denied-contribution
  counts.
- **Labels** — session, project, profile, supervised-tool and configuration
  labels.
- **Model usage** — LLM provider, model, token counts, and cost in integer USD
  micros, with the price source and pricing version.
- **Destination rollups** — keyed by a **team-scoped HMAC**. A clear hostname
  appears only if the team's owner enables approved labels, and that applies
  prospectively.
- **Security events** — queue, deny, canary and explicit data-gap events.
- **Device health** — last contact, latest local event, dirty and archive
  backlog, completeness tier, audit-database generation.

## What is never sent

- Command lines and arguments.
- Raw file paths and URLs.
- Prompts and model responses.
- File or source contents, and payload bodies.
- Environment values and secrets.
- Free-form task context and decision reasons.

None of these have a column in the wire schema or the archive schema. The
exporter has no field to put them in.

<Callout type="info" title="Not anonymous">
The payload carries team, actor and device identity — that is what makes
per-developer cost and per-session drill-down possible. It is aggregated, not
anonymised.
</Callout>

## Cadence

Each device sends a heartbeat every **30 seconds**, and a snapshot on the same
30-second tick whenever there is anything new to send. Target visibility in the
online dashboard is **60 seconds p95** while the device is connected — near
real-time, not real-time.

## Devices

Every machine registers as a **device**: a server-issued device id plus a
one-time secret, stored locally with owner-only permissions.

The allowance is **two active devices per seat, capped at 50 per team**. That
cap is enforced at cloud registration only — it never degrades local security
or supervision. A device that cannot register still supervises normally; it
just has nowhere to publish its rollups.

Devices can be revoked from the team dashboard.

## Turning it on and off

```
grith analytics status      # show the current state for this machine
grith analytics enable      # turn it on and record the consent receipt
grith analytics disable     # stop uploading from this machine
```

`disable` stops further uploads. It does not delete data that has already
synced — that is managed from the dashboard.

Setting `general.audit_sync = false` stops cloud analytics entirely.

See [`grith analytics`](/docs/cli/analytics) for the full command reference.

## Cost tracking

Each provider call's metadata — provider, model, prompt tokens, completion
tokens — is captured locally. The rollup carries the token counts and the cost
in integer USD micros, along with the price source and the pricing version used
to compute it, so a later price change doesn't silently restate history.

Cost is attributed by the labels in the rollup: session, project, profile and
supervised tool, against the team, actor and device the snapshot came from.

## The daily archive

After a UTC day closes and the server has accepted that day's rollups, the
device exports the day's row-level analytics projection as a **Parquet** object
and uploads it to private S3 storage. It carries the same operand-free fields
as the rollups, one row per event — never the excluded content above.

Objects are content-addressed and encrypted at rest with a customer-managed KMS
key. The bucket blocks public access and requires TLS.

<Callout type="warning" title="Checksum-verified, not signed">
Archive integrity is **checksum-verified, not signed**. Before activating an
object the server verifies its size, SHA-256 checksum, encryption and key
identity. Device signing keys exist in the protocol but are not yet verified,
so do not treat archived objects as signed, immutable or tamper-proof.

This is separate from the local audit log, which is hash-chained and
tamper-evident on the device. See
[Logging & audit retention](/docs/ops/logging-and-audit-retention).
</Callout>

## Retention

| Data | Retention |
| --- | --- |
| Cloud rollups | 90 days |
| Cloud security events | 90 days |
| Cloud analytics archive, active | 90 days |
| Cloud analytics archive, superseded revisions | 7 days |
| Local Pro analytics projection | 90 days |
| Local active audit database | 30 days |
| Local cold audit archives | No automatic expiry; user-managed |

When an entitlement expires, cloud data becomes **inaccessible immediately** and
is **deleted after a 30-day reactivation window**.

Deleting a team removes both the cloud rollups and the archived objects. Object
deletion runs as a separate job, and the deletion is not complete until that job
succeeds.

## Exporting analytics

Export the local audit records behind these analytics as JSON or CSV:

```
grith audit export --format json
grith audit export --format csv
```

The export reads the local audit database on the machine that recorded it, so
it covers that device's own history rather than the team-wide totals shown in
the online dashboard.

For deeper compliance integration (SIEM export, custom shapes), see
[Compliance reporting (Enterprise)](/docs/enterprise/compliance-reporting).
