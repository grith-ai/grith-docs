## General

### Is grith a sandbox?

No. grith decides whether a syscall runs; the kernel still runs it. The agent
operates against the real filesystem, real network, real OS. Containment is
opt-in via [zones](/docs/concepts/session-containment), but those score-based,
not kernel-enforced.

If you want hard isolation, run grith _inside_ a container or user namespace.
The two are complementary.

### Does grith require root?

No. grith uses ptrace, which on default Linux configurations works without
root for processes you spawn yourself. See
[Installation: permissions](/docs/start/installation#permissions).

### Does grith slow my agent down?

Not noticeably for normal interactive use. Typical pipeline latency is 8–12ms;
agents usually wait on the model for hundreds of ms per turn. Heavy syscall
workloads (large file scans, refactors writing many files) add measurable
overhead — see [Performance & tuning](/docs/ops/performance-tuning).

### Does grith call out to grith.ai?

grith contacts grith.ai for:

- Update checks (daily, disable with `update_check = false`).
- Profile update checks (weekly, disable with `profile_update_check = false`).
- License refresh (every 6 hours on Pro).
- Cloud analytics, on a paid plan. It is on by default and publishes aggregated
  rollups and security events every 30 seconds — see
  [Analytics & cost](/docs/pro/analytics-and-cost) for the full payload. Turn it
  off with `grith analytics disable` or `general.audit_sync = false`.

It does NOT send:

- Raw audit records. Nothing uploads the audit log itself.
- Command lines and arguments, raw file paths, URLs.
- Prompts, model responses, source code, file contents, payload bytes.
- Environment values and secrets.
- Provider API keys.

## Platforms

### Does it work on macOS / Windows?

Not in v0.2. The supervisor uses ptrace+seccomp, which is Linux-specific.
macOS and Windows ports are in active development for v2.0.

Until then: Linux VM, container, or Docker. grith in a container works fine.

### Does it work on aarch64?

Yes. grith runs natively on Linux aarch64 (kernel 5.3+) — the supervisor has a
per-architecture register and syscall-number backend, and the release ships a
static `aarch64-unknown-linux-musl` binary. Raspberry Pi 4/5, AWS Graviton, and
Ampere are all supported. The one-line installer picks the right binary
automatically.

### Does it work on NixOS / Arch / Fedora / etc?

Yes. grith ships as a statically-linked musl binary (x86_64 and aarch64) that
works on any Linux distro. The shipping install script is distro-aware for placement; the
binary itself doesn't care.

## Filters

### Can I turn off a specific filter?

Yes, in `~/.config/grith/config.toml`:

```toml
[proxy.filters.behavioural]
enabled = false
```

But understand what you're losing — each filter exists for a reason. Disable
sparingly and consider raising `auto_allow_threshold` instead.

### Can I add my own filter?

Custom filters are an Enterprise feature in v0.1. They're authored in Rust and
shipped via the [centralised policy bundle](/docs/pro/centralised-policies).
Open-source custom filter SDK is planned for v0.2.

### Why does the secret scanner have so many patterns?

1,620+ patterns covers a wide credential vocabulary (cloud providers, SaaS
APIs, CI/CD, databases, crypto, etc). The cost is small — Aho-Corasick / regex
sets are linear in content length, not in pattern count.

## Pricing

### How much does Pro cost?

$25/user/month monthly, $21/user/month annual (≈17% off). Up to 25 users. See
[grith.ai/pricing](https://grith.ai/pricing).

### Is the community edition feature-limited?

No. The community edition is the full grith product — all 18 filters, the
supervisor, the digest, all CLI tools. Pro adds team-scope features (sync,
shared keys, channels, analytics).

### Is there a free trial?

The community edition is free forever, no trial required. Pro features can
be evaluated by signing up at grith.ai/teams — first 14 days don't bill.

## Privacy / security

### Where do my API keys live?

Local: `~/.config/grith/keys/<provider>.key` (perms 0600). For Pro teams,
optionally synced encrypted from the dashboard — never visible to grith.ai in
plaintext. See [Encrypted key management](/docs/pro/encrypted-key-management).

### Where does my audit log live?

Local: `~/.local/share/grith/audit/audit.db`. The audit log itself never leaves
the machine. On a paid plan, cloud analytics publishes aggregated rollups and
security events derived from it — counts, score histograms, per-filter activity
and labels, never the records themselves. It is on by default and turned off
with `grith analytics disable` or `general.audit_sync = false`.

### Can grith see my source code?

It sees the _fact_ of file reads (paths, sizes, timestamps), not the
contents — grith never stores file or payload bytes in the audit log. The model
that's running inside your agent sees the content; that's between you and your
provider.

### What about my chat history with the model?

grith doesn't see it. The agent talks to the provider; grith only sees the
syscalls the agent makes as a result.
