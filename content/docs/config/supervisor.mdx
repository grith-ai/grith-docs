## Notes

- **`enabled`** — when `false`, `grith exec` falls back to a no-op pass-through
  (useful for testing wrapper compatibility without enforcing). Audit log still
  records calls.
- **`default_profile`** — applied when `--profile` isn't passed to `grith exec`.
  Conservative default: `generic`.
- **`freeze_timeout_seconds`** — how long a frozen process can wait for a digest
  decision before grith auto-denies. Should match (or be slightly less than)
  `[proxy] review_timeout_seconds`.
- **`max_concurrent_sessions`** — soft cap on simultaneous supervised sessions.
  Exceeding it returns an error from `grith exec` rather than degrading
  performance.
- **`pty_forwarding`** — required for interactive agents. Disabling breaks
  agent TUIs.
- **`require_sandbox`** — when `true`, refuses to supervise unless the process is
  running inside a container or user namespace. Belt-and-braces.

## Workspace trust

`${PROJECT_DIR}` in a profile's `routine_paths` expands to the directory you ran
`grith exec` in — and only that directory. In a multi-worktree layout that means
the sibling worktrees of the very repository you are working on get no trust at
all, and a tool working in one of them prompts on work that would be silent one
directory over.

- **`include_linked_worktrees`** — extend the session's project trust to every
  git worktree of the launch repository. Default `true`. The listing includes
  the main worktree, so launching from a subdirectory trusts the repository root
  as well. Resolved once at session start and never re-read: a re-read would let
  the supervised tool widen its own trust with `git worktree add`.

  git builds its worktree list from files inside the repository, which the
  supervised tool can write, so a reported worktree earns trust only if it also
  sits inside the directory the repository itself lives in, carries git's own
  back-pointer to this repository, and is not a credential or personal-data
  directory. A repository checked out directly into your home directory gets no
  linked-worktree trust at all — its enclosing directory would be the whole of
  `$HOME`. Declare `additional_project_roots` for that layout.

- **`additional_project_roots`** — extra roots for layouts git cannot infer: a
  worktree of a _different_ repository parked alongside this one, or a non-git
  sibling checkout. `${HOME}`, `${PROJECT_DIR}` and `~` expand as in
  `routine_paths`.
- **`restrict_to_workspace`** — turn the workspace into a boundary rather than a
  trusted region. File operations outside it are denied instead of scored. See
  [Workspace-only sessions](/docs/cli/exec#workspace-only-sessions) for exactly
  what stays reachable, and `grith exec --workspace-only` for the per-session
  form. Default `false`.

Trust here is project-derived, never literal: `/`, your home directory and any
ancestor of it are refused however they are declared, at most 32 roots are
trusted per session, and credential stores inside a trusted root (`~/.ssh`,
`~/.aws`, `.npmrc`, …) still go to the security proxy.

## Platform mechanisms

The supervisor uses different OS mechanisms per platform. v0.2 supports
**ptrace + seccomp on Linux x86_64 and aarch64**; other platforms ship in v2.0.
See
[Syscall interception](/docs/concepts/syscall-interception) for mechanism details.

## Noise reduction

The most useful knobs are:

- **`ignore_read_only`** — skip filter pipeline for `read` syscalls on already-open
  fds (the `open` was already scored). Default `true`.
- **`batch_rapid_reads`** — coalesce rapid reads from the same fd into a single
  filter pass per `batch_window_ms`. Default 50ms window.

Both are safe to leave on. Disable only for forensic recording where you want
every syscall captured raw (use `--trace-syscalls-jsonl` on `grith exec` for that).
